# Breaking API Changes: v3.x → v4.0.0

v4.0.0 is generated by [Fern](https://buildwithfern.com/) from the same OpenAPI specification that generated v3.x with Stainless. The package name `hiddenlayer-sdk`, the `hiddenlayer` import, the `HiddenLayer` and `AsyncHiddenLayer` clients, the environment variables, the model and community scanners and the red team sessions all stay. Every method v3.10.0 had keeps its name and path. What changes is the minimum Python, the client options, the names of the response types, pagination, errors and how per-request options are passed. v4.0.0 also adds every API in the specification that v3.x didn't cover.

## Python 3.10

v4.0.0 needs Python 3.10 or later, and is tested on 3.10 to 3.14. v3.x supported Python 3.9, which reached end of life on 2025-10-31. On Python 3.9, pip keeps installing v3.10.0.

## Imports

```python
# v3.x and v4.0.0
from hiddenlayer import HiddenLayer, AsyncHiddenLayer
from hiddenlayer import ModelScanner, CommunityScanner, BetaWarning, warn_beta
```

Types move from the `hiddenlayer.types` packages, one per resource, to the package root:

```python
# v3.x
from hiddenlayer.types.scans import ScanReport

# v4.0.0
from hiddenlayer import ScanReportOfRecordV3
from hiddenlayer.lib import ScanReport  # the same class, under its v3.x name
```

A few types that only one group of methods uses are exported from that group's module instead, such as `hiddenlayer.scans.StartUploadResponse`. [Methods and types](#methods-and-types) gives the module of each. `hiddenlayer.resources`, `hiddenlayer.pagination` and every module whose name starts with an underscore are gone.

`BaseClient` and `AsyncBaseClient`, in `hiddenlayer.base_client`, are the generated clients without the scanners, the red team sessions, credentials from `HIDDENLAYER_TOKEN` or beta warnings. Use `HiddenLayer` and `AsyncHiddenLayer`.

## Client options

Every option is a keyword argument, as in v3.x.

| v3.x | v4.0.0 |
|---|---|
| `bearer_token` | `token`, a string or a function returning one; `AsyncHiddenLayer` also takes `async_token`, an async function |
| `client_id`, `client_secret` | unchanged |
| `environment="prod-us"` or `"prod-eu"` | unchanged; `HiddenLayerEnvironment.PROD_US` and `.PROD_EU` also work |
| `base_url` | unchanged, as a `str` (v3.x also took an `httpx.URL`) |
| `timeout`, a `float` or an `httpx.Timeout` | `timeout`, in seconds, as a `float`; for an `httpx.Timeout`, pass an `httpx_client` built with it |
| `max_retries` | unchanged |
| `default_headers` | `headers` |
| `default_query` | none; pass `additional_query_parameters` in each call's `request_options` |
| `http_client` | `httpx_client` |
| none | `follow_redirects`, `logging` |

```python
# v3.x
client = HiddenLayer(bearer_token="...", default_headers={"X-Team": "ml-platform"}, timeout=30.0)

# v4.0.0
client = HiddenLayer(token="...", headers={"X-Team": "ml-platform"}, timeout=30.0)
```

A v3.x-only option raises `TypeError`, as any unexpected keyword argument does.

`base_url` wins over `environment`. v3.x raised `ValueError` when `environment` was passed while `HIDDENLAYER_BASE_URL` was set; v4.0.0 uses `environment`. `HIDDENLAYER_BASE_URL` is used only when neither option is given.

These are removed:

- `client.copy()` and `client.with_options()`: construct another client, or pass [`request_options`](#per-request-options-and-raw-responses) to one call.
- `client.close()` and using the client as a context manager: to close connections yourself, pass an `httpx_client` and close that.
- `DefaultHttpxClient`: pass an `httpx.Client`. v4.0.0 gives its own client a 60-second timeout and has it follow redirects, as v3.x did; set both on a client you pass in.
- `client.bearer_token`, `client.client_id`, `client.client_secret`, `client.base_url`, `client.timeout` and `client.max_retries`: the client no longer exposes its options.

Requests send `User-Agent: hiddenlayer-sdk/4.0.0` (v3.x: `HiddenLayer/Python 3.x`) and `X-Fern-*` headers in place of the `X-Stainless-*` ones.

## Environment variables

| Variable | v4.0.0 |
|---|---|
| `HIDDENLAYER_TOKEN` | read, as in v3.x, unless a token or client credentials are passed |
| `HIDDENLAYER_CLIENT_ID`, `HIDDENLAYER_CLIENT_SECRET` | read, as in v3.x: exchanged at `/oauth2/token` for an access token, which is reused until two minutes before it expires |
| `HIDDENLAYER_BASE_URL` | read, as in v3.x, unless `environment` or `base_url` is passed |
| `HIDDENLAYER_LOG` | no longer read; pass `logging={"level": "debug", "silent": False}` |
| `HIDDENLAYER_CUSTOM_HEADERS` | no longer read; pass `headers` |

The variables are read when a client is constructed, as in v3.x.

Credentials passed as arguments win over the environment, and a token wins over client credentials: `token`, then `client_id` and `client_secret`, then `HIDDENLAYER_TOKEN`, then `HIDDENLAYER_CLIENT_ID` and `HIDDENLAYER_CLIENT_SECRET`. Either client credential may come from the environment when the other is passed. A blank value counts as not set. In v3.x, client credentials from either place overrode a token from either place, so a setup with all three variables set now sends the token.

A client with no credentials at all can still be constructed, but each request raises an `ApiError` that names the arguments and variables to set. v3.x sent the request with no `Authorization` header. For a deployment that takes unauthenticated requests, pass a placeholder such as `token="unauthenticated"`.

## Methods and types

Every method v3.10.0 had is on the same path in v4.0.0, with the same positional arguments unless the table says otherwise. v3.x named each response type after its method; v4.0.0 names it after the specification's schema. A v4.0.0 type is imported from `hiddenlayer` unless it is prefixed with its module, as in `scans.StartUploadResponse` for `hiddenlayer.scans.StartUploadResponse`.

| Method | v3.10.0 returns | v4.0.0 returns | Arguments |
|---|---|---|---|
| `models.retrieve` | `ModelRetrieveResponse` | `SensorSorModel` | unchanged |
| `models.delete` | `None` | `None` | unchanged |
| `models.cards.list` | `SyncOffsetPage[CardListResponse]` | `SyncPager[ModelCardV4, ModelCardV4QueryResponse]` | unchanged |
| `evaluations.red_team.create` | `RedTeamCreateResponse` | `StartWorkflowResponse` | unchanged |
| `evaluations.red_team.retrieve_evaluation_results` | `RedTeamRetrieveEvaluationResultsResponse` | `WorkflowResultResponse` | unchanged |
| `evaluations.red_team.retrieve_next_action` | `RedTeamRetrieveNextActionResponse` | `NextActionResponse` | unchanged |
| `evaluations.red_team.retrieve_status` | `RedTeamRetrieveStatusResponse` | `WorkflowStatusResponse` | unchanged |
| `evaluations.red_team.submit_target_response` | `RedTeamSubmitTargetResponseResponse` | `SubmitTargetResponseResult` | unchanged |
| `evaluations.red_team.terminate` | `None` | `None` | unchanged |
| `prompt_analyzer.create` | `PromptAnalyzerCreateResponse` | `HiddenLayerPromptAnalyzerResponse` | `x_requester_id` is now `requester_id` |
| `interactions.analyze` | `InteractionAnalyzeResponse` | `EnrichedResponse` | unchanged |
| `runtime.evaluate_interaction` | `RuntimeEvaluateInteractionResponse` | `InteractionEvaluationResponse` | unchanged |
| `runtime.evaluate_request` | `RuntimeEvaluateRequestResponse` | `ProviderPayload` | `body` is now `request` |
| `runtime.evaluate_response` | `RuntimeEvaluateResponseResponse` | `ProviderPayload` | `body` is now `request` |
| `sensors.create` | `SensorCreateResponse` | `SensorSorItemResponse` | unchanged |
| `sensors.retrieve` | `SensorRetrieveResponse` | `SensorSorItemResponse` | unchanged |
| `sensors.update` | `SensorUpdateResponse` | `SensorSorUpdateResponseModel` | unchanged |
| `sensors.delete` | `None` | `None` | unchanged |
| `sensors.query` | `SensorQueryResponse` | `SyncPager[SensorSorItemResponse, SensorSorQueryResponse]`, [now paginated](#pagination) | unchanged |
| `scans.results.list_files` | `SyncCursorPagination[ScanFileResult]` | `SyncPager[ScanFileResultWithComplianceV3, scans.ListFilesResultsResponse]` | new, optional: `include_threat_types`, `sort` |
| `scans.results.retrieve_summary` | `ScanReportSummary` | `ScanReportSummaryResponseV3` | new, optional: `include_threat_types` |
| `scans.results.sarif` | `str` | `str` | new, optional: `include_threat_types` |
| `scans.jobs.retrieve` | `ScanReport` | `ScanReportOfRecordV3` | new, optional: `include_threat_types` |
| `scans.jobs.list` | `JobListResponse` | `SyncPager[ScanReportOfRecordV3Summary, scans.ListJobsResponse]`, [now paginated](#pagination) | new, optional: `finding_severity`, `include_threat_types`, `threat_type` |
| `scans.jobs.request` | `ScanJob` | `ScanJob` | new, optional: `scan_id`, `status` |
| `scans.upload.complete_all` | `UploadCompleteAllResponse` | `scans.CompleteAllUploadResponse` | unchanged |
| `scans.upload.start` | `UploadStartResponse` | `scans.StartUploadResponse` | unchanged |
| `scans.upload.file.add` | `FileAddResponse` | `scans.upload.AddFileResponse` | unchanged |
| `scans.upload.file.complete` | `FileCompleteResponse` | `scans.upload.CompleteFileResponse` | `(file_id, scan_id=...)` is now `(scan_id, file_id)` |

The async client returns `AsyncPager` where the table says `SyncPager`.

The v3.10.0 types the table doesn't show as a whole response map as follows: `CardListResponse` → `ModelCardV4`; `ScanFileResult` → `ScanFileResultWithComplianceV3`, a `ScanFileResultV3` with the file's compliance; `JobListResponse` → `scans.ListJobsResponse`; `SensorQueryResponse` → `SensorSorQueryResponse`; `ResultSarifResponse` → `str`. v3.10.0's `api.md` also listed `FileScanReport`, which the package never defined; v4.0.0 has `FileScanReportV3`, the file results of a report.

The `*Params` types under `hiddenlayer.types`, which described each method's keyword arguments, have no v4.0.0 counterpart: the arguments are on the method's signature.

```python
# v3.x
client.scans.upload.file.complete(file_id, scan_id=scan_id)
client.prompt_analyzer.create(prompt="...", x_requester_id="user-1234")

# v4.0.0
client.scans.upload.file.complete(scan_id, file_id)
client.prompt_analyzer.create(prompt="...", requester_id="user-1234")
```

## Request and response models

- **Nested request objects are models.** An argument such as `interactions.analyze`'s `metadata` is typed as a model, `InteractionsMetadata`, where v3.x typed it as a `TypedDict`. A dict with the same keys is still sent as it was, but a type checker reports it.
- **Fields that v3.x left as dicts are models.** `WorkflowResultResponse.result.report`, for example, was `Dict[str, object]` and is a `RedTeamReport`, so `report["summary"]["total_sessions"]` becomes `report.summary.total_sessions`.
- **Responses are validated.** A response that doesn't match its model raises `hiddenlayer.core.ParsingError`, with the response's `status_code`, `headers` and `body`, and the validation error as `cause`. It is not an `ApiError`. v3.x built the model without validating it unless the client was constructed with `_strict_response_validation=True`.
- **Models are immutable.** Assigning to a field raises.
- **`to_dict()` and `to_json()` are removed.** Use `model.dict()` and `model.json()`, which write the API's field names and leave out fields the response didn't set, or pydantic's `model_dump()` and `model_dump_json()`.
- **A field the API adds later** is still readable as an attribute, and enumerated values still accept strings the SDK doesn't know yet.

Pydantic 1.9.2 or later and pydantic 2 are both supported, as in v3.x.

## Pagination

List methods return a `SyncPager`, or an `AsyncPager` from the async client. Iterating one still walks every item across pages.

| | v3.x | v4.0.0 |
|---|---|---|
| Every item | `for item in client.models.cards.list()` | unchanged |
| Every item, async | `async for item in client.models.cards.list()` | `async for item in await client.models.cards.list()` |
| The current page's items | `page.results` or `page.items`, by endpoint | `page.items` |
| Whether there is another page | `page.has_next_page()` | `page.has_next` |
| The next page | `page.get_next_page()` | `page.next_page()`, or `None` after the last |
| Every page | `page.iter_pages()` | unchanged |
| The response envelope | the page itself | `page.response` |

`page.next_page_info()` is removed.

Two methods change shape on purpose. In v3.x they returned the raw response envelope; in v4.0.0 they return a pager of its items:

| Method | v3.x | v4.0.0 |
|---|---|---|
| `scans.jobs.list` (`GET /scan/v3/results`) | `JobListResponse`, with `items`, `total`, `limit` and `offset` | `SyncPager[ScanReportOfRecordV3Summary, scans.ListJobsResponse]`; the envelope is `page.response` |
| `sensors.query` (`POST /api/v2/sensors/query`) | `SensorQueryResponse`, with `results`, `total_count`, `page_number` and `page_size` | `SyncPager[SensorSorItemResponse, SensorSorQueryResponse]`; the envelope is `page.response` |

```python
# v3.x
response = client.sensors.query(filter={"active": True})
print(response.total_count)
for sensor in response.results:
    print(sensor.sensor_id)

# v4.0.0
page = client.sensors.query(filter={"active": True})
print(page.response.total_count)
for sensor in page:
    print(sensor.sensor_id)
```

## Errors

Errors no longer share the `HiddenLayerError` base. An error response raises `hiddenlayer.core.ApiError` or one of its subclasses, each with `status_code`, `headers` and the decoded `body`.

| v3.x | v4.0.0 |
|---|---|
| `HiddenLayerError`, `APIError` | none; catch `hiddenlayer.core.ApiError` for API responses |
| `APIStatusError`, with `status_code`, `response` and `body` | `hiddenlayer.core.ApiError`, with `status_code`, `headers` and `body` |
| `BadRequestError` (400) | `BadRequestError` |
| `AuthenticationError` (401) | `UnauthorizedError` |
| `PermissionDeniedError` (403) | `ForbiddenError` |
| `NotFoundError` (404) | `NotFoundError` |
| `ConflictError` (409) | `ConflictError` |
| `UnprocessableEntityError` (422) | `UnprocessableEntityError` |
| `RateLimitError` (429) | `ApiError` with `status_code == 429` |
| `InternalServerError` (any 5xx) | `InternalServerError` (500), `BadGatewayError` (502), `ServiceUnavailableError` (503), or `ApiError` for another 5xx |
| `APIResponseValidationError` | `hiddenlayer.core.ParsingError` |
| `APITimeoutError` | `httpx.TimeoutException` |
| `APIConnectionError` | `httpx.TransportError` |

The typed errors are exported from `hiddenlayer` and `hiddenlayer.errors`, with `ContentTooLargeError`, `GoneError`, `NotImplementedError`, `PreconditionFailedError` and `UnsupportedMediaTypeError`. A method raises a typed error only for the statuses its endpoint declares, and a plain `ApiError` for any other, so match on `status_code` when the status is what matters:

```python
# v3.x
import hiddenlayer

try:
    client.sensors.retrieve("unknown")
except hiddenlayer.APIStatusError as error:
    print(error.status_code, error.body)

# v4.0.0
from hiddenlayer.core import ApiError

try:
    client.sensors.retrieve("unknown")
except ApiError as error:
    print(error.status_code, error.body)
```

408, 409, 429 and 5xx responses and failed connections are still retried twice by default, with exponential backoff. A request that times out is no longer retried.

## Per-request options and raw responses

The `extra_headers`, `extra_query`, `extra_body` and `timeout` arguments of every method become one `request_options` argument:

```python
# v3.x
client.sensors.retrieve(sensor_id, timeout=5.0, extra_headers={"X-Trace": "abc"})
client.with_options(max_retries=5).sensors.retrieve(sensor_id)

# v4.0.0
client.sensors.retrieve(
    sensor_id,
    request_options={"timeout": 5.0, "max_retries": 5, "additional_headers": {"X-Trace": "abc"}},
)
```

`request_options` also takes `additional_query_parameters` and `additional_body_parameters`.

`with_raw_response` stays, and returns an `HttpResponse` with `data`, `headers` and `status_code`:

```python
# v3.x
response = client.sensors.with_raw_response.retrieve(sensor_id)
sensor = response.parse()

# v4.0.0
response = client.sensors.with_raw_response.retrieve(sensor_id)
sensor = response.data
```

`with_streaming_response` is removed, and so are `client.get`, `client.post` and the other methods for undocumented endpoints.

## Model and community scanners

`client.model_scanner` (`scan_file`, `scan_folder`, `scan_s3_model`, `scan_azure_blob_model`, `scan_huggingface_model`, `scan_result`) and `client.community_scanner` (`community_scan`, `scan_result`) keep their arguments, defaults and behaviour, on both clients. What changes:

- They return `ScanReport`, which is now `ScanReportOfRecordV3`, with the fields v3.10.0's `ScanReport` had. `hiddenlayer.lib.ScanReport` is the same class.
- A file a scan refuses is reported by the generated client's `BadRequestError`, and a scan that isn't found by its `NotFoundError`.
- A part with no start offset or upload URL raises `ValueError` (v3.x: `Exception`).

`boto3`, `azure-identity`, `azure-storage-blob` and `huggingface_hub` stay optional: install the ones for the scans you run.

## Red team sessions

`client.evaluation_sessions.red_team` (`start_session`, `resume_session`, `terminate_session`) and the sessions it returns keep their methods and defaults. What changes:

- **Errors are the documented ones.** v3.x caught `httpx.HTTPStatusError`, which its client never raised, so its translations never ran and the client's own errors reached the caller. v4.0.0 raises what the v3.x docstrings said:
  - `WorkflowNotFoundError` for a workflow the API doesn't know, from `resume_session`, `terminate_session`, `get_next_action` and `wait_for_completion`. v3.x raised `NotFoundError`.
  - `RedTeamSessionError` for any other error from `resume_session` or `terminate_session`, and for a 500 from `get_next_action`, with the workflow's status when it can be read.
  - `InvalidSessionError` when `run_with_callback_parallel` submits a response and the API answers 400.
- **`wait_for_completion` polls through a 408, 429 or 5xx** until `max_wait`, and raises any other API error at once. v3.x raised every API error at once.
- **A poll that outlasts `poll_max_wait` raises `PollTimeoutError`**, a `RedTeamSessionError`. v3.x raised a bare `Exception` with the same message.
- **`start_session` takes `None` for an option that isn't sent**, where v3.x took its `omit` sentinel. The defaults are the same.
- **`severity_mapping`'s values** are typed as `HighestSeverity`, the same five strings.
- **Actions are `NextActionResponse`**, and `retrieve_evaluation_results` returns a `WorkflowResultResponse` whose `report` is a model ([Request and response models](#request-and-response-models)).
- The sync session's `wait_for_completion(verbose=True)` no longer asks asyncio for an event loop, which raises `RuntimeError` on Python 3.14 when none is running.

## Beta warnings

The first call to a beta endpoint still emits a `BetaWarning`. Three things change:

- The warning names the endpoint by HTTP method and path, where v3.x named the method:

  ```
  [BETA] GET /evaluations/v1/red-team/{workflow_id}/status: This endpoint is not GA or Production ready and is subject to changes at any time. Breaking changes may occur.
  ```

- Each client warns once for each endpoint, whatever the warnings filter, and clients that share an `httpx_client` warn once between them. Under a filter that turns `BetaWarning` into an error, every call raises.
- The list of beta endpoints follows the API's, so it now covers every beta endpoint in v4.0.0, not only the ones v3.x had.

`warn_beta(name)` stays. `hiddenlayer.lib.check_beta_endpoint(url)` takes the HTTP method as an optional second argument, and warns on every call. `hiddenlayer.lib._beta_endpoints.BETA_ENDPOINTS` is removed.

## Dependencies

- `requests`, `requests-auth`, `types-requests`, `anyio`, `distro` and `sniffio` are no longer installed with the SDK. `httpx`, `pydantic` and `typing_extensions` stay, and `pydantic-core` is new.
- The `aiohttp` extra stays: `pip install hiddenlayer-sdk[aiohttp]`. With it installed, `AsyncHiddenLayer` uses aiohttp by default; v3.x used it only when `http_client=DefaultAioHttpClient()` was passed. `DefaultAioHttpClient` and `DefaultAsyncHttpxClient` are still exported.

## Removed

- `client.copy()`, `client.with_options()`, `client.close()`, the context manager, `DefaultHttpxClient`, `default_query`, `HIDDENLAYER_LOG` and `HIDDENLAYER_CUSTOM_HEADERS`, covered above.
- `with_streaming_response`, `client.get` and its siblings, and `page.next_page_info()`, covered above.
- `file_from_path`: the API has no file-upload parameters; the model scanner uploads files itself.
- `NOT_GIVEN`, `NotGiven`, `Omit`, `omit` and `not_given`: leave an optional argument out.
- `Client` and `AsyncClient`, the aliases of `HiddenLayer` and `AsyncHiddenLayer`.
- `Timeout`, `Transport`, `ProxiesTypes`, `Stream`, `AsyncStream`, `APIResponse`, `AsyncAPIResponse`, `BaseModel`, `ENVIRONMENTS`, `DEFAULT_TIMEOUT`, `DEFAULT_MAX_RETRIES`, `DEFAULT_CONNECTION_LIMITS` and `__title__`. `hiddenlayer.core.RequestOptions` is a different type from v3.x's `RequestOptions`.

## New APIs

v4.0.0 covers every public operation in the specification, 207 in all, against 29 in v3.10.0, including access, asset inventory, audit, compliance, credentials, governance, metrics, MITRE ATLAS, model intelligence, permissions, roles, SSO integrations, supply chain, triage and users. [reference.md](../reference.md) lists each method.

## Migration checklist

- [ ] Run on Python 3.10 or later.
- [ ] Rename `bearer_token`, `default_headers` and `http_client` to `token`, `headers` and `httpx_client`.
- [ ] If a token and client credentials are both set, check that the token is the one to use.
- [ ] Replace types imported from `hiddenlayer.types.*` with the v4.0.0 names, from `hiddenlayer`.
- [ ] Rename `x_requester_id`, and `body` on `runtime.evaluate_request` and `evaluate_response`; swap the arguments of `scans.upload.file.complete`.
- [ ] Iterate `scans.jobs.list` and `sensors.query` as pages, or read `page.response`; add `await` before an async pager.
- [ ] Replace `APIStatusError` and its subclasses with `ApiError` and the typed errors; catch httpx's errors for timeouts and failed connections.
- [ ] Move `timeout`, `extra_headers`, `extra_query` and `extra_body` into `request_options`.
- [ ] Replace `response.parse()` with `response.data`.
- [ ] Read red team reports as models, and catch `WorkflowNotFoundError` where `NotFoundError` was caught.
